# 小黄人 (Minion) 开发计划 — 2026-06-01

> 架构依据：[ADR-006](../docs/decisions/006-minion-embodiment-architecture.md)
> 模块文档：[voice-gateway.md](../docs/modules/voice-gateway.md) · [minion-body.md](../docs/modules/minion-body.md)
> 架构总览：[architecture.md](../docs/architecture.md) → "Embodiment / Device Layer"

端到端实体小黄人：3D 外壳 + 树莓派 + 麦克风 + 摄像头 + 舵机/LED；能力 = 唤醒 → 语音对话 → 视觉 → 动作/表情。
第一优先级：**对话自然流畅 + 音色好听**。

## 一、三条铁律（决定排序）

1. **Outside-in TDD** — 每个 runner 增量先写跨边界 acceptance test（红）再实现。
2. **Fakes-first** — 先用 `FakeDevice` 在笔记本跑通整条链路，再投入云/硬件（对标 `CliExecutor` 的 Local/Fake seam）。
3. **Additive-only** — runner 全部加法，不碰 `Tool`/`MCP` 对外接口（见 CLAUDE.md "Public API Stability"）。

## 三、四个里程碑（纵切片，逐个可演示）

### M0 — 全仿真闭环（无硬件、无云，跑笔记本）✅（runner 侧）
- 范围：R1 · R2 · R3 · R5；G1（纯文本桥）；B1（FakeDevice：喂文本+固定图，打印 actuator 指令）
- **Done**：`MinionLoopM0AcceptanceTest` 跑绿——
  `假唤醒 → 假转写 → LLM → look 返回固定图 + move 假舵机日志 → 多模态再答 → N×带情绪 SPEAKABLE_CHUNK`
  （fakes 在测试内；Python minion-body(B1) / voice-gateway(G1) 骨架已按本测试锁定的契约落地为独立仓）
- 价值：用假件验证契约对不对，零成本。

### M1 — 接真云语音（仍无硬件）
- 范围：G2 流式 STT · G3 流式 TTS+viseme · G4 barge-in；R3 · R4；B2 音频 I/O
- **Done**：对笔记本说话 → 厂商音色流式应答 → 能打断 → **实测首次出声 < ~1.3s**

### M2 — 上树莓派，能动能看
- 范围：B3 唤醒+VAD(Pi) · B4 真 GPIO 的 MCP 工具 · B6 舵机+OLED 眼+摄像头；R5 端到端
- **Done**：实体小黄人喊它会醒、能对话、`look` 抓帧进 LLM、能挥手/转头

### M3 — 拟人化 / 表情同步打磨
- 范围：B5 Realizer 全量（viseme 口型 + emotion 眼睛 + bookmark 手势 + idle 基线）；主动 TriggerSource（看到人脸打招呼）；人格 Skills
- **Done**：口型对得上、眼睛会表达、空闲有微动作

## 四、早期风险探针（提前打，别等里程碑暴雷）

- **延迟**：M1 前做最小 spike 串 STT→LLM→TTS 量首响（"自然流畅"成败点）
- **厂商 viseme/流式 TTS**：M1 选型先验 Azure `VisemeReceived` / Polly Speech Marks 的实时性与音色
- **Pi 算力**：M2 前确认 Pi 同跑 唤醒+VAD+音频流 不卡

## 五、起手式

从 **R1** 开始——最独立、纯本仓、可立刻按 payload-capture acceptance test 验证。R1 绿 → R2 → R3/R4，之后才需起 G/B 两个新仓。

## 六、延后项（ADR-006 D7）

物理安全（将来必落设备端）、二进制媒体走 runner、重视觉（持续目标跟踪/本地人脸识别）。
