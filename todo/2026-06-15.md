## P0: Context Compaction — Upgrade to Progressive Multi-Layer Pipeline

**Current state:** 2-layer compaction (SnipCompactor + MicroCompactor chain).

**Industry benchmark (Claude Code):** 5-layer progressive pipeline:
1. Snip Compact — local removal, no API call (runner has this)
2. Micro Compact — cache-aware truncation (runner has this)
3. Context Collapse — archive old messages, project collapsed view at query time, pre-select reduction candidates
4. Auto-Compact — summarize old conversation history via LLM API call
5. Progressive Summarization — at 90% usage begin grouped section summarization (90% → 92% → 94% thresholds)

**Gap:** Missing layers 3-5. Current hard-cutoff approach risks "cliff-edge" information loss. Industry data shows 65% of enterprise agent failures stem from context drift/memory loss.

**TODO:**
- [ ] Add `ContextCollapseCompactor` (Layer 3): archive-and-project pattern with pre-selected reduction candidates; on 413 error, immediately commit pending candidates
- [ ] Add `AutoCompactor` (Layer 4): LLM-based summarization of old conversation history (use a cheaper/faster model)
- [ ] Add `ProgressiveSummarizer` (Layer 5): graduated summarization at configurable usage thresholds (default 90%/92%/94%)
- [ ] Refactor `ContextCompactor` into a composable chain with configurable layers
- [ ] Add context usage metrics to `CostTracker` to trigger progressive compaction

**References:** Claude Code context compaction (y-agent.github.io), Anthropic context engineering docs, LangGraph checkpointer pattern

## P0: Error Resilience — Circuit Breaker + Retry Policies

**Current state:** `CostTracker` for budget limits, `CancellationToken` for user-initiated cancel. No tool-level or LLM-level failure isolation.

**Industry benchmark:**
- LangGraph: per-node `RetryPolicy(max_attempts=3, backoff_factor=2)` + superstep atomic rollback
- 2026 best practices: circuit breaker pattern (temporarily disable failing tools/APIs), exponential backoff with jitter
- Pipeline reliability math: 99.5% per-step = only 96.5% for 7-step pipeline

**Gap:** A single tool timeout or LLM 429 can stall the entire agent loop. No automatic retry, no circuit breaking, no graceful degradation.

**TODO:**
- [ ] Add `RetryPolicy` config per tool (max attempts, backoff factor, jitter) in `ToolExecutor`
- [ ] Add `CircuitBreaker` for tool execution: track failure rate per tool, temporarily disable after N consecutive failures, auto-reset after cooldown
- [ ] Add LLM-level retry with exponential backoff + jitter for transient errors (429, 5xx) in `LLMProvider` implementations
- [ ] Add per-error-code policies: 429 → retry with backoff; 5xx → retry; 4xx → fail fast without retry
- [ ] Add atomic rollback semantics to `ToolCallingLoop`: if parallel tool execution partially fails, allow configurable policy (fail-all, succeed-partial)
- [ ] Ensure all tool implementations are idempotent for safe retry

**References:** LangGraph error handling (DeepWiki), 5 AI Agent Error Handling Patterns (DEV.to)

## P0: Agent Coordination — Synchronous Handoff-as-Tool

**Current state:** Only async subagent pattern (`SpawnSubagentTool` → `WaitSubagentTool` → `ListSubagentsTool`). Orchestrator routes by agentId in metadata.

**Industry benchmark:**
- OpenAI Agents SDK: `Handoff` is a specialized tool call; Runner switches active agent and passes full conversation history
- AutoGen Swarm: agents declare handoff targets; LLM generates `Handoff` tool call to transfer control
- LangGraph: `Command(goto=<agent>, update=<state>)` combining control flow + state mutation
- Semantic Kernel: `HandoffOrchestration` with human-in-the-loop support

**Gap:** No synchronous agent-to-agent transfer. Current spawn/wait is cumbersome for sequential delegation. The LLM must manage spawn→wait→collect manually, wasting tokens and increasing error surface.

**TODO:**
- [ ] Add `TransferToAgentTool`: synchronous handoff where control transfers entirely to target agent with full conversation context
- [ ] Support handoff callbacks (on_handoff) for pre-transfer processing
- [ ] Consider LangGraph-style `Command` object unifying control flow (goto) + state mutation (update) in a single return value
- [ ] Add `active_agent` tracking in `InterruptibleRun` state for handoff-based orchestration
- [ ] Update `AgentRouter` to support tool-initiated routing (not just metadata-based)

**References:** OpenAI Agents SDK handoffs, AutoGen Swarm pattern, LangGraph Command pattern

## P1: Advisor/Middleware Chain — Pre+Post Processing Pipeline

**Current state:** `StreamPostProcessorPipeline` handles only post-processing (risk control, deeplinks, tracing, speakable chunks). No composable pre-processing middleware.

**Industry benchmark (Spring AI):**
- `Advisor` interface hierarchy: `CallAdvisor`, `StreamAdvisor`, `BaseAdvisor`
- Ordered chain-of-responsibility: pre-process request → call LLM → post-process response
- Built-in advisors: `ToolCallingAdvisor`, `MessageChatMemoryAdvisor`, `ReReadingAdvisor`, `SemanticCacheAdvisor`
- Composable, ordered, works for both sync and reactive paths

**Gap:** Memory injection, guardrail checks, caching, and request augmentation are currently ad-hoc in `AgentLoop`. No clean extension point for pre-processing middleware.

**TODO:**
- [ ] Design `AgentAdvisor` interface with `adviseCall()` and `adviseStream()` methods
- [ ] Implement `AgentAdvisorChain` (ordered chain-of-responsibility)
- [ ] Migrate memory injection from `AgentLoop` into `MemoryAdvisor`
- [ ] Migrate `StreamPostProcessorPipeline` into post-processing advisors
- [ ] Add `SemanticCacheAdvisor` for caching identical/similar requests
- [ ] Ensure advisor chain works for both sync and `Flux<StreamEvent>` paths

**References:** Spring AI Advisor pattern, augmentcode.com agentic design patterns

## P1: Dynamic Tool Search — Token-Efficient Tool Discovery

**Current state:** All registered tools are passed as `toolDefinitions` to every LLM call. Tool count grows with MCP servers and skills.

**Industry benchmark:**
- Claude Code: tool search for dynamic discovery (schemas appended, not swapped, preserving prompt cache)
- Spring AI `ToolSearchToolCallingAdvisor`: sends only a single search tool initially, dynamically expands matching tools on demand; achieved **34-64% token savings**
- Anthropic recommendation: "For large tool sets, use dynamic tool discovery"

**Gap:** Token waste scales linearly with tool count. With MCP servers adding dozens of tools, this becomes a real cost/latency issue.

**TODO:**
- [ ] Implement `ToolSearchTool`: a meta-tool that searches the registry by name/description and returns matching tool schemas
- [ ] Add dynamic tool injection: when `ToolSearchTool` returns results, append those tool schemas to the next LLM call (not swap — preserve cache)
- [ ] Make this configurable: below N tools, send all; above N, use search-first strategy
- [ ] Track token savings metrics to validate the approach

**References:** Spring AI ToolSearchToolCallingAdvisor, Claude Code tool search pattern

## P1: Memory — Tiered Architecture with Cross-Session Knowledge

**Current state:** `MemoryProvider` with session-key namespacing, ephemeral/durable write, BM25+vector hybrid search. Single-tier: all history in same store.

**Industry benchmark:**
- CrewAI: 4 memory types (Short-Term/Long-Term/Entity/Contextual)
- LangGraph: Checkpointer (thread-scoped snapshots) + Store (cross-thread key-value)
- Anthropic: File-based persistent memory (`/memories` directory) + grep-based search
- 2026 best practices: 3-tier (hot: last ~10 turns verbatim; warm: summarized; cold: vector store)

**Gap:** No tiered retrieval (all history treated equally → "lost-in-the-middle" effect). No cross-session entity memory. No automatic summarization of older turns.

**TODO:**
- [ ] Implement tiered retrieval: hot layer (recent N turns, verbatim in context), warm layer (summarized older turns), cold layer (vector store for semantic search)
- [ ] Add `EntityMemory`: extract and persist key entities (people, projects, preferences) across sessions
- [ ] Add `MemoryStore` interface for cross-session key-value storage (separate from conversation history)
- [ ] Implement automatic warm-tier summarization (compress older segments while preserving essential info)
- [ ] Add memory search relevance scoring to prioritize hot > warm > cold results

**References:** CrewAI memory system, LangGraph Store, Anthropic memory architecture

## P1: Checkpointing — Automatic State Persistence for Fault Tolerance

**Current state:** `InterruptibleRun` supports user-initiated interrupt/resume. No automatic checkpointing.

**Industry benchmark:**
- LangGraph: Checkpointer persists full state snapshot after each superstep; enables resume-after-failure, time-travel debugging, human-in-the-loop interrupts
- Google ADK Java: Event-sourcing model with immutable Event objects for auditability and replay

**Gap:** If the JVM crashes mid-agent-loop, all in-flight state is lost. No replay capability for debugging complex agent interactions.

**TODO:**
- [ ] Design `Checkpoint` abstraction: snapshot of conversation state, tool results, and agent metadata at a point in time
- [ ] Implement `CheckpointStore` SPI with `InMemoryCheckpointStore` (dev) and `SqliteCheckpointStore` (prod)
- [ ] Add checkpointing hooks in `ToolCallingLoop`: save checkpoint after each tool execution round
- [ ] Enable resume-from-checkpoint: on restart, detect incomplete runs and offer to resume
- [ ] Add time-travel debugging API: list checkpoints for a session, replay from any checkpoint
- [ ] Consider event-sourcing model: record all interactions as immutable events, derive current state from event log

**References:** LangGraph Checkpointer, Google ADK Event model

- [ ] Add heartbeat configuration to `AgentProfile` (interval, prompt, enabled)

## P2: Streaming Modes — Delta/Update Mode

**Current state:** Single streaming mode — `Flux<StreamEvent>` emitting full events.

**Industry benchmark (LangGraph):** 4 streaming modes:
1. **values** — full state after each superstep
2. **updates** — delta per node (only what changed)
3. **messages** — LLM token stream
4. **events** — fine-grained lifecycle events

**Gap:** Clients that only need token-level streaming or state deltas waste bandwidth receiving full events.

**TODO:**
- [ ] Add `StreamMode` enum: `EVENTS` (current), `DELTAS` (only changed fields), `TOKENS` (LLM token stream only)
- [ ] Implement delta computation in `StreamEventSerializer`
- [ ] Allow clients to specify preferred mode via `GatewayRequest`
- [ ] Emit structured terminal event so clients know stream is complete without relying on connection close

**References:** LangGraph streaming modes

## P2: Testing Infrastructure — Agent-Level Test Tier + Deterministic Replay

**Current state:** Good outside-in TDD discipline, `CapturingLLMProvider` for payload capture, integration seam tests.

**Industry benchmark:**
- 5-level test pyramid: unit (200/commit), agent (single agent vs faked tools), integration (multi-agent vs in-memory fakes, 50/PR), system (full orchestration), acceptance (E2E, 10/nightly)
- WireMock/VCR-style: record/replay LLM HTTP responses for deterministic regression tests
- Evaluation-first development: define capabilities and eval sets before coding

**Gap:** Missing "agent-level" test tier (single agent against faked tool responses to verify tool selection and sequencing). No deterministic replay of real LLM responses.

**TODO:**
- [ ] Add `AgentTestHarness`: runs a single agent against a set of faked tool responses, asserts tool selection order and final output
- [ ] Add LLM response recording/replay (WireMock-style): record real LLM HTTP responses, replay for deterministic tests
- [ ] Add eval framework: define expected capabilities as test cases, run agents against eval sets, track pass rates over time
- [ ] Add CI gate with threshold: agent eval pass rate must be > N% to merge
- [ ] Document test pyramid ratios: unit (most), agent, integration, acceptance (least)

**References:** WireMock for LLM testing, Spring AI evaluator, OpenAI Evals

## Architectural Strengths (Keep/Reinforce)

These aspects of runner already match or exceed industry best practices:

1. **Reactive-first with Flux<StreamEvent>** — ahead of CrewAI/AutoGen which lack unified cross-agent streaming
2. **Events as typed enum values** — cleaner than string conventions used by many frameworks
3. **ToolPolicy composable permissions** (ALLOW/DENY/ABSTAIN chain) — matches OpenAI scoped access patterns
4. **Outside-in TDD with CapturingLLMProvider** — aligns with the 5-level test pyramid's "mock the LLM" approach
5. **ScopedToolRegistry per agent** — directly parallels industry's "minimum-required permissions per agent" pattern
6. **RiskLevel across MCP boundary** — unique; most frameworks don't propagate risk metadata across protocol boundaries
7. **Public API stability enforcement** — rare in agent frameworks; this prevents the "framework churn" problem
8. **Docs-first workflow** — prevents the doc drift that plagues fast-moving agent framework projects
9. **ServiceLoader SPI for providers** — clean, zero-coupling provider discovery without Spring DI dependency in kernel
