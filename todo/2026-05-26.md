### TODO-054: ClaudeProvider OkHttpClient 资源泄漏风险

**文件**: `agent-kernel/.../llm/claude/ClaudeProvider.java:63`

**问题**:
- `new OkHttpClient()` 无自定义配置：无 connect/read/write timeout、无连接池限制

- SSE 流式路径（L177）BufferedReader 在异常时可能不关闭

**Reference**:
- Claude Code: 对每种请求类型配置独立超时（streaming 无上限但有 heartbeat 检测，non-streaming 30s）
- OpenClaw: 所有 HTTP 客户端使用统一配置工厂，含连接池 + circuit breaker

**Action**:
- [ ] 为 OkHttpClient 配置 `connectTimeout(10s)`、`readTimeout(60s)`、`writeTimeout(30s)`
- [ ] 为 SSE 流式请求配置 `readTimeout(0)` + 自定义 heartbeat 检测（30s 无数据则断开）
- [ ] HTTP 错误响应解析为 `LLMProviderException` 而非原始文本
- [ ] SSE 解析添加 try-with-resources 保证 BufferedReader 关闭
- **Priority**: P1 — 生产环境下资源泄漏可导致连接耗尽
- **Effort**: 1d

- reactive 路径 `completeStreamReactive()` 重试整个请求，客户端可能已收到部分 TEXT_DELTA → 重试后重复发送

**Reference**:
- Reactor 标准实践：使用 `Mono.delay()` / `retryWhen(Retry.backoff())` 替代 Thread.sleep()
- Claude Code: streaming 重试仅在 connection 建立前失败时触发，stream 中断后不重试

**Action**:
- [ ] `completeStreamReactive()` 改用 Reactor `retryWhen(Retry.backoff(maxRetries, firstBackoff))`
- [ ] 区分 pre-stream failure（可重试）和 mid-stream failure（不可重试，已有数据发出）
- [ ] 同步路径 `Thread.sleep()` 保留但添加注释说明仅用于 sync 调用
- **Priority**: P1 — 高并发下线程池耗尽风险
- **Effort**: 1d

### TODO-066: SubagentRuntime UUID 截断 — 碰撞风险

**文件**: `agent-kernel/.../orchestrator/SubagentRuntime.java:81`

**问题**:
- Session key 使用 `UUID.randomUUID().toString().substring(0, 8)` — 仅 8 个十六进制字符
- 8 字符 = 32 位 → birthday paradox 下 ~65536 个 subagent 后 50% 碰撞概率
- 虽然单 session 不太可能达到此数量，但跨 session 累积的 `completedRuns` 缓存可能碰撞

**Action**:
- [ ] 使用完整 UUID（36 字符）或至少 12 字符（48 位，~1600 万个才 50% 碰撞）
- [ ] 或使用 `UUID.randomUUID().toString().replace("-", "")` 完整 32 字符 hex
- **Priority**: P3 — 当前规模下概率极低
- **Effort**: 0.1d
