# Architecture Optimization TODO - 2026-04-18

> Cross-analysis of Runner project vs OpenClaw, Claude Code (leaked source), and open-source AI agent framework best practices (LangGraph, CrewAI, AutoGen, OpenAI Agents SDK, Vercel AI SDK, Semantic Kernel).

---

## Current Architecture Strengths

Runner already implements many production-grade patterns:

- **Reactive-first streaming** (Flux<StreamEvent>) with typed event enum and factory methods
- **4-layer Multi-Agent Orchestrator** with ScopedToolRegistry (deny > allow)
- **5 tool supply pathways** (SPI, manual, plugin, MCP, CLI)
- **Full-duplex interrupt/resume** via InterruptibleRun + CancellationToken
- **Context budget** with CompactionChain (Snip + Micro) and CostTracker
- **3-layer memory** (Session + Ephemeral + Durable) with BM25 + Vector hybrid search
- **Outside-in TDD** enforced with acceptance tests driving design

## P0 - Critical (Architecture/Safety)

### TODO-001: BashTool Sandboxing
- **Gap**: CliTool uses `ProcessBuilder` directly with no sandboxing, no command blacklist, no resource limits
- **Reference**: Claude Code classifies tools by risk level (read-only vs. state-modifying vs. system-altering); BashTool is highest risk with permission gating
- **Action**:
  - [ ] Add command denylist (rm -rf, dd, mkfs, shutdown, etc.)
  - [ ] Add resource limits (CPU time, memory, file descriptors) via ulimit/cgroups
  - [ ] Add working directory restriction (cannot escape project root)
  - [ ] Add timeout enforcement at OS level (not just Java timeout)
  - [ ] Consider Docker/container isolation for production deployments
- **Module**: agent-tools (CliTool)

### TODO-002: Input Validation at API Boundaries
- **Gap**: GatewayRequest fields not validated; tool arguments parsed from LLM without schema validation
- **Reference**: All major frameworks validate at system boundaries; OpenAI Agents SDK has Guardrails; Vercel AI SDK uses Zod schemas
- **Action**:
  - [ ] Add JSR-303 Bean Validation on GatewayRequest (sessionKey, messages not null/empty)
  - [ ] Validate tool arguments against JSON Schema before execution in ToolExecutor
  - [ ] Add prompt injection detection (pattern matching for adversarial input)
  - [ ] Add request size limits (max message count, max message length)
- **Module**: agent-kernel (Gateway, ToolExecutor), agent-web (controllers)

### TODO-003: LLM Streaming Timeout
- **Gap**: No explicit timeout on LLM streaming calls; if provider hangs, stream blocks indefinitely
- **Reference**: Claude Code has request-level timeout context; all production frameworks enforce deadlines
- **Action**:
  - [ ] Add `timeout()` Reactor operator on LLM Flux with configurable deadline
  - [ ] Add request-level timeout context (overall request deadline, not just per-LLM-call)
  - [ ] Emit TIMEOUT StreamEvent before termination for client notification
- **Module**: agent-kernel (ToolCallingLoop, ResilientLLMProvider)

### TODO-004: Rate Limiting
- **Gap**: Zero rate limiting implementation despite 20+ files referencing the concept
- **Reference**: All production frameworks enforce per-user, per-agent, per-tool rate limits
- **Action**:
  - [ ] Add per-session request rate limiter (Bucket4j or Resilience4j RateLimiter)
  - [ ] Add per-user token budget limiter (daily/hourly caps)
  - [ ] Add per-tool execution frequency limiter (prevent infinite tool loops)
  - [ ] Return 429 + Retry-After header on rate limit exceeded
- **Module**: agent-web (interceptor/filter), agent-kernel (ToolExecutor)

## P1 - Important (Production Readiness)

### TODO-005: Circuit Breaker for LLM Providers
- **Gap**: ResilientLLMProvider has retry + health tracking but no circuit breaker; after 3 failures marks UNHEALTHY but keeps sending requests
- **Reference**: Industry standard Closed/Open/Half-Open pattern; Microsoft recommends circuit breaker for all AI agent dependencies
- **Action**:
  - [ ] Add Resilience4j CircuitBreaker wrapping LLM provider calls
  - [ ] Configure failure rate threshold (e.g., 50% in 10s window → open)
  - [ ] Add fallback to secondary LLM provider when circuit opens
  - [ ] Emit PROVIDER_FALLBACK StreamEvent on fallback activation
- **Module**: agent-kernel (ResilientLLMProvider)

### TODO-006: Multi-Level Context Compaction (Claude Code Pattern)
- **Gap**: Runner has 2-level compaction (Snip + Micro). Claude Code has 5 strategies: MicroCompact, AutoCompact (at 92% utilization), Context Collapse, Session Memory, Full Compact
- **Reference**: Claude Code triggers AutoCompact at ~92% context utilization with 13K token reserve buffer
- **Action**:
  - [ ] Add compaction trigger threshold (fire at 90-92% context utilization, not just on iteration)
  - [ ] Add Session Memory compactor: extract key decisions/state to external storage (like MemoryProvider durable section)
  - [ ] Add Full Compact strategy: LLM-generated structured summary when context is critical
  - [ ] Add compaction reserve buffer (always keep N tokens free for model response)
  - [ ] Implement BATS-style budget regimes (HIGH >=70%, MEDIUM 30-70%, LOW 10-30%, CRITICAL <10%) in CostTracker
- **Module**: agent-kernel (ContextCompactor, CompactionChain, CostTracker)

### TODO-007: Differentiated Subagent Modes
- **Gap**: Runner has single subagent spawn model. Claude Code has 3 modes: Fork (lightweight, context-inherited), Teammate (parallel, file mailbox), Worktree (git-isolated)
- **Reference**: Claude Code Fork has 200-turn limit, returns <500 words; Worktree gets its own branch per agent
- **Action**:
  - [ ] Add Fork mode: lightweight subagent inheriting parent context, cache-optimized, result-size-limited
  - [ ] Add Worktree mode: git worktree per agent for parallel file modifications without conflicts
  - [ ] Add SubagentMode enum to SpawnSubagentTool parameters
  - [ ] Add result size limit per mode (Fork: 500 words, Teammate: unlimited)
- **Module**: agent-kernel (SubagentRuntime, SpawnSubagentTool)

### TODO-008: OpenTelemetry Integration
- **Gap**: Custom Tracer (SpanContext, StreamEventSpanExporter) not compatible with OTel standard; no distributed tracing, no metrics
- **Reference**: OpenAI Agents SDK has built-in tracing; industry converging on OpenTelemetry
- **Action**:
  - [ ] Add opentelemetry-sdk dependency
  - [ ] Bridge custom Tracer to OTel SpanExporter (preserve existing StreamEventSpanExporter)
  - [ ] Add MDC context propagation (requestId, sessionId, agentId) to all log statements
  - [ ] Add Micrometer metrics: LLM latency histogram, tool execution counter/timer, token consumption gauge
  - [ ] Add health check endpoint with provider status (ResilientLLMProvider.HealthStatus)
- **Module**: agent-kernel (trace/), agent-web (actuator config)

### TODO-009: Structured Logging
- **Gap**: Plain text SLF4J logging without trace IDs, MDC context, or JSON format
- **Reference**: All production agent frameworks use structured JSON logging with correlation IDs
- **Action**:
  - [ ] Configure Logback with JSON encoder (logstash-logback-encoder)
  - [ ] Add MDC filter: inject requestId, sessionId, agentId, userId into every log line
  - [ ] Add structured fields: toolName, provider, model, tokenCount to relevant logs
  - [ ] Add audit trail logging for tool executions (who, what, when, result status)
- **Module**: agent-web (logback config), agent-kernel (MDC propagation)

### TODO-010: User-Configurable Hook System
- **Gap**: AgentObserver is developer-facing only. No user-configurable hooks (unlike Claude Code's `.claude/hooks.json`)
- **Reference**: Claude Code allows shell commands triggered by events (before/after tool, on error, on complete); OpenClaw has event-driven triggers
- **Action**:
  - [ ] Design hook configuration format (YAML/JSON file per workspace)
  - [ ] Add hook trigger points: beforeToolCall, afterToolCall, onError, onComplete, onAgentStart
  - [ ] Add hook executor (shell command, HTTP webhook, or inline script)
  - [ ] Add pre-tool-call hooks with abort capability (hook can reject a tool call)
  - [ ] Add hook isolation (timeout, error handling for hook failures)
- **Module**: agent-kernel (new hooks/ package)

## P2 - Enhancement (Best Practice Alignment)

### TODO-011: Guardrail Framework
- **Gap**: soul-safety handles psychological content only; no general-purpose input/output guardrails
- **Reference**: OpenAI Agents SDK has first-class Guardrails; Claude Code has 7-mode permission system with ML classifier
- **Action**:
  - [ ] Design Guardrail interface: `validate(input/output) -> GuardrailResult(pass/fail/warning)`
  - [ ] Add input guardrails: prompt injection detection, content policy, size limits
  - [ ] Add output guardrails: PII filtering, structured output validation (JSON Schema), content safety
  - [ ] Add human-in-the-loop guardrail: pause execution for user approval on high-risk operations
  - [ ] Integrate with ScopedToolRegistry permission model

### TODO-012: Deferred MCP Tool Schema Loading
- **Gap**: McpToolSourceProvider loads all tool schemas upfront into context
- **Reference**: Claude Code loads only tool names initially; full schemas fetched on demand to reduce context overhead
- **Action**:
  - [ ] Load only tool names + short descriptions from MCP servers at startup
  - [ ] Fetch full JSON Schema on first use of each tool
  - [ ] Cache schemas after first load
  - [ ] Reduces context consumption when many MCP tools are registered

### TODO-013: Workspace-as-Config (OpenClaw Pattern)
- **Gap**: AgentProfile is code-defined; requires recompilation to change agent identity
- **Reference**: OpenClaw uses SOUL.md / AGENTS.md / TOOLS.md files for agent configuration; version-controllable, diffable
- **Action**:
  - [ ] Support file-based AgentProfile definition (YAML/Markdown in workspace directory)
  - [ ] Add file watcher for hot-reload on profile file changes
  - [ ] Support SOUL.md equivalent: system prompt + personality in Markdown
  - [ ] Support TOOLS.md equivalent: tool permissions in structured format

### TODO-014: Heartbeat / Proactive Agent
- **Gap**: Agents only activate on user messages; no autonomous periodic execution
- **Reference**: OpenClaw's HEARTBEAT.md allows cron-like periodic agent turns; Claude Code's KAIROS has 5-minute daemon cycles
- **Action**:
  - [ ] Add Heartbeat interface: periodic agent turns without user input
  - [ ] Add cron-like scheduling (interval-based or cron expression)
  - [ ] Add heartbeat session isolation (separate from user sessions)
  - [ ] Use cases: inbox triage, status monitoring, proactive notifications

### TODO-015: Permission Tiering (Claude Code Pattern)
- **Gap**: ScopedToolRegistry has binary allow/deny; no risk-level classification
- **Reference**: Claude Code has 3-tier access: (1) fixed allowlist for read-only, (2) in-scope writes auto-approved, (3) everything else through classifier
- **Action**:
  - [ ] Add ToolRiskLevel enum: READ_ONLY, WRITE_IN_SCOPE, WRITE_OUT_OF_SCOPE, SYSTEM_MODIFY
  - [ ] Annotate each tool with risk level
  - [ ] Auto-approve READ_ONLY tools; require confirmation for SYSTEM_MODIFY
  - [ ] Consider ML classifier for ambiguous cases (future)

### TODO-016: State Snapshots & Checkpoint/Replay
- **Gap**: No serialized agent state checkpoints; no replay capability for debugging
- **Reference**: LangGraph has built-in checkpointing with time travel; Claude Code has session memory extraction
- **Action**:
  - [ ] Add AgentStateSnapshot: serialize conversation context, tool results, memory index at each step
  - [ ] Add checkpoint persistence (file or database)
  - [ ] Add replay mode: re-execute from checkpoint with modified input
  - [ ] Use for debugging failed agent runs

### TODO-017: Plugin System Modernization
- **Gap**: Legacy Plugin class; no dynamic JAR loading, no dependency resolution, no versioning
- **Reference**: Semantic Kernel has full plugin lifecycle; modern frameworks support hot-reload
- **Action**:
  - [ ] Implement plugin JAR discovery from `plugins/` directory
  - [ ] Add classloader isolation per plugin
  - [ ] Add plugin lifecycle hooks (onLoad, onUnload, onUpgrade)
  - [ ] Add plugin dependency resolution (DAG)
  - [ ] Add plugin version conflict detection

### TODO-018: Performance Benchmarks
- **Gap**: No JMH benchmarks, no load testing framework, no latency SLAs
- **Action**:
  - [ ] Add JMH benchmarks for hot paths (ToolCallingLoop, ContextCompactor, ToolRegistry lookup)
  - [ ] Add load test: 100/1000 concurrent sessions with mock LLM
  - [ ] Establish latency SLAs per component
  - [ ] Add chaos test: inject provider failures, measure recovery time

- **Action**:
