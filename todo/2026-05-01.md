## 一、外部参照物更新（2026-05-01 新增发现）

### 1.1 Claude Code 泄漏源码：深层设计模式

| 设计点 | 实现细节 | 对 runner 的启示 |
|--------|----------|------------------|
| **5 层 Compaction Cascade** | Budget Reduction → Snip → Microcompact → Context Collapse → Auto-Compact；逐级升级，最廉价优先；Auto-Compact 在 83.5% context 触发，保留 13K token buffer，3 次失败后熔断 | runner 有 2 层(Snip+Micro)，缺 Context Collapse（只读投影不变异历史）和 Auto-Compact（LLM 摘要） |
| **canUseTool 中心权限门** | 所有工具调用过 canUseTool：deny → ask → allow，首条匹配即决；与 allowedTools/disallowedTools 配置分离 | runner 的 ScopedToolRegistry 只有 deny > allow 二元过滤，缺 "ask"（交互式确认）层 |
| **Auto Mode ML 分类器** | Sonnet 4.6 拦截每次工具调用，评估三类风险：scope escalation / untrusted infrastructure / session drift | runner 无 ML 分类器，工具风险完全靠静态配置 |
| **Interactive Streaming Queue** | 异步双缓冲队列，支持运行中重定向（mid-task steering），无需全量重启 | runner 的 InterruptibleRun 支持中断/恢复，但不支持"不中断的方向修正" |
| **Worktree 子代理隔离** | `isolation: worktree` 给子代理独立 git worktree，变更通过正常 git 操作合并 | runner SubagentRuntime 无文件系统隔离 |
| **27 Hook Event Types** | 5 个安全相关，含 PreCompact（exit code 2 可阻止压缩）、StopFailure、Notification(permission_prompt/idle_prompt) | runner AgentObserver 有 9 个钩子，缺 PreCompact / StopFailure / Notification |
| **98.4% 确定性基础设施** | 仅 1.6% 是 AI 决策逻辑，其余为权限门、上下文管理、工具路由、恢复逻辑 | 架构思维转变：agent 框架的核心不是 AI，而是确定性基础设施 |

### P1 — 架构增强（生产就绪度）

#### TODO-A01: 3 层 Compaction 升级为 5 层 *(演进 TODO-006)*
- **现状**: CompactionChain(Snip, Micro) = 2 层。已是可用状态。
- **参考**: Claude Code 5 层级联：Budget Reduction → Snip → Microcompact → Context Collapse → Auto-Compact
- **关键设计**:
  - Budget Reduction: 对单个超限 tool output 截断，零 API 开销
  - Context Collapse: 只读投影（read-time projection），不变异完整历史，按 feature flag 门控
  - Auto-Compact: 语义压缩，保留 13K token buffer，生成 ≤20K token 摘要；3 次失败后熔断
  - 触发阈值: ~83.5% context window（可配置 `AUTOCOMPACT_PCT_OVERRIDE`）
- **参考2**: Mastra Observational Memory — Observer + Reflector 后台 agent 将旧消息压缩为结构化观察
- **动作**:
  - [ ] 新增 BudgetReductionCompactor: 在 Snip 前对单个超大 tool_result 预截断
  - [ ] 新增 ContextCollapseCompactor: 不变异消息链，只在查询时生成压缩视图
  - [ ] 新增 AutoCompactor: fork 子 LLM 调用生成结构化摘要；加熔断器（3 次失败后停止）
  - [ ] CompactionChain 扩展为 5 阶段：Budget → Snip → Micro → Collapse → Auto
  - [ ] CostTracker 新增 compaction 触发阈值（默认 83.5%）
  - [ ] 新增 COMPACTION_TRIGGER StreamEvent 事件类型
- **模块**: agent-kernel (ContextCompactor, CompactionChain, CostTracker)

## 三、架构合理性分析总结

### 当前架构优势（保持）

1. **Reactive-first**: `Flux<StreamEvent>` 作为统一流式抽象，背压、组合操作符完备
2. **4 层 Orchestrator**: Profile → Registry → Orchestrator → SubagentRuntime 层次清晰
3. **SPI 无硬编码**: LLMProviderFactory, ToolSourceProvider 全 ServiceLoader 驱动
4. **Outside-in TDD**: 接受测试先行，6 条 UT 规则防传输链断裂
5. **事件即公民**: StreamEvent.EventType 枚举 + 工厂方法，杜绝 TRACE + 字符串约定
6. **CompactionChain**: 2 层已上线，架构支持扩展到 5 层
7. **MessageSnapshot**: 不可变快照解耦持久化与 API 调用路径

### 需要补强的架构维度

| 维度 | 差距 | 参照物 | 优先级 |
|------|------|--------|--------|
| **安全硬化** | 无输入校验、无限流、无限频、无沙箱 | 所有生产框架 | P0 |
| **Compaction 深度** | 2/5 层 | Claude Code 5 层 | P1 |
| **权限模型** | 二元 deny/allow | Claude Code deny/ask/allow + ML | P1 |
| **确定性工作流** | 无 | Google ADK workflow agents / OpenClaw Lobster | P2 |
| **协议对齐** | 仅 MCP 基础 | MCP 2025-11-25 + AG-UI + A2A v1.2 | P2-P3 |
| **中间件管道** | 通知式 observer | LangGraph wrap-style / Microsoft filters | P2 |
| **可观测性** | 自定义 Tracer | OTel 行业标准 | P1 |
| **运行中转向** | 只能中断/恢复 | Claude Code steering / OpenClaw active-run | P2 |
