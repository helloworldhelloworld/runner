# ADR-024：内容绑定的配置发布与持久生效

- 日期：2026-09-07
- 状态：Accepted
- 前置：ADR-017、021、023

## 问题

当前 Skill 发布只检查 skillId 最近一次通过率；测试后修改草稿仍可发布。版本先被标记 active，
之后注册提示错误只写日志。多个状态更新没有事务，重启后 native 不恢复已发布配置。

## 决策

1. TestRun 持久保存测试时的候选内容、用例/验证器版本及各自摘要。候选摘要排除 active/draft 等
   管理状态，包含实际提示、工具名称、触发条件和其他配置；评测记录独立于候选。旧无绑定报告
   保留查询，不能自动成为新版发布凭证。
2. stage 验证阈值、非零且完整的完成结果、内容摘要与当前草稿一致，并将被测候选原样保存为版本。
   测试/取消/缺失结果必须进入明确失败或取消终态，不能留下可用于发布的 completed 空报告。
3. activate 校验版本归属、冻结内容、原测试报告及评测绑定，先完整解析并验证配置，再事务更新
   同一 Skill 的 active 指针/归档状态。保留兼容入口，增加显式 expected-active 条件更新接口。
   更新失败时原 active 保留；回滚验证目标属于同一个 Skill。
4. active 版本库是发布配置的权威来源。发布服务提供 PromptSource，native 从持久 active 版本
   组合内容快照；重启直接恢复，旧执行保留 ADR-023 快照，新执行采用新版本。
   PromptEngine/InstructionRegistry 注册作为兼容视图，不承担 native 生效状态的权威职责。
5. 配置发布不授予工具权限；需要的工具必须存在且实际调用仍通过运行策略。Skill 的受控测试
   只覆盖其声明的配置，不批准任意运行时代码部署；完整源码/用例回归继续使用 ADR-021 候选包。

## 验收

真实 SQLite、发布服务、Spring 装配及 Provider HTTP：测试→修改草稿→stage 拒绝；通过内容→
stage→激活→下一次请求含同一内容；失败保留旧 active；跨 Skill 回滚拒绝；并发条件更新只成功一次；
重建服务/数据库连接后仍能恢复；旧执行不受新发布影响。报告与草稿/用例篡改分别验证。
