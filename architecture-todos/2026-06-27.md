### 1.1 Claude Code v2.1.195 新增关键设计（vs 2026-04 基线）

| 设计点 | 实现方式 | 对 runner 的启示 |
|---|---|---|
| **五层 Compaction 管线** | 实际为 5 层递进：(1) Budget Reduction（截断单个大输出）→ (2) Snip（归档旧消息）→ (3) Microcompact（基于 cache 状态清理旧工具结果）→ (4) Context Collapse（归档+投影折叠视图）→ (5) Auto-compact（唯一调 LLM 的层，摘要压缩至原文 ~12%）；触发阈值 ~83%，可配置 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` | runner 有 Snip+Micro（对应 2+3 层）但**缺 Budget Reduction / Context Collapse / Auto-compact**（1/4/5 层）；长会话仍可能爆 context |

| **Agent Teams（P2P 多智能体）** | 实验性功能：多个 Claude Code 实例通过**磁盘上的 JSON 邮箱 + 共享任务列表**进行对等通信；无需中心协调 | runner 只有 hub-and-spoke 的 SubagentRuntime，无 peer-to-peer |

## 二、现状架构痛点（2026-06-27 盘点）

### P0 — 影响主链路稳定性 / 性能

1. **五层 Compaction 管线的缺失层** `agent-kernel/.../context/`
   - 症状：runner 仅实现了 5 层管线中的 2 层（Snip = 第 2 层，Micro = 第 3 层）；缺少 Budget Reduction（第 1 层，截断单个 >50K char 工具输出到 ~2KB 预览+磁盘路径）、Context Collapse（第 4 层，识别逻辑段并分组摘要）、Auto-compact（第 5 层，fork 子 agent 做全量语义摘要，压缩至 ~12%）。
   - 参考：Claude Code 五层递进"lazy degradation"策略，最便宜的先跑。
   - 目标：
     - **Budget Reduction**：`ToolCallingLoop` 在收到工具结果时，若超过阈值（默认 50K chars），写入磁盘并替换为预览+文件路径。成本最低，优先实现。
     - **Context Collapse**：在 `CompactionChain` 中 Micro 之后追加；识别逻辑段（同一 tool 的多轮结果、同一主题的对话段）并分组摘要。
     - **Auto-compact**：在 `CompactionChain` 末尾追加；使用 `LLMProvider` 做摘要调用；支持可配置触发阈值（默认 90% context window）。
   - 落点：`AgentLoop.buildMessages` → `CompactionChain.compact()` → 五层按序执行。
   - 注意：Auto-compact 需要 `LLMProvider` 引用，设计上通过 `Supplier<LLMProvider>` 或 `CompactionContext` 避免循环依赖。

2. **Deferred Tool Loading / Tool Search 缺失** `agent-kernel/.../agent/ToolRegistry.java`, `agent-mcp/`
   - 症状：所有已注册工具（含 MCP 远程工具）的完整 schema 全量注入 LLM context；工具越多 context 越浪费。
   - 参考：Claude Code 默认延迟加载，85% context 减少。
   - 目标：`ToolRegistry` 新增 `getDeferredToolDefinitions()`（仅返回名称+简介）；`ToolSearchTool`（内置工具）按需加载完整 schema；`LLMOptions.toolDefinitions` 区分 deferred vs upfront。
   - MVP：对 MCP 工具默认 defer，本地工具保持 upfront。

3. **WebSocket 端口安全审计** `agent-web/.../websocket/`
   - 症状：OpenClaw v2026.3.11 修复了同样的 WebSocket 劫持漏洞（本地进程可拦截 agent-to-skill 通信）。runner 的 Vert.x WebSocket (port 8081) 如果绑定 `0.0.0.0` 而非 `127.0.0.1`，存在同类风险。
   - 目标：审计绑定地址；在非生产部署默认 `127.0.0.1`；添加 origin 校验。

### P1 — 扩展性与开发体验

4. **声明式 Agent Profile 配置** `agent-web/.../config/OrchestratorConfig.java`
   - 症状：persona 定义（default / worker / minion）硬编码在 Java `@Configuration` 中；添加/修改 agent 必须改代码重启。
   - 参考：Claude Code `.claude/agents/` YAML 文件 + OpenClaw SOUL.md/AGENTS.md。
   - 目标：支持从 `agents/` 目录加载 YAML/JSON 格式的 `AgentProfile` 定义；hot-reload 支持（watch 目录变化）；保留代码注册作为优先级更高的覆盖。

5. **声明式 Hook 配置** `agent-kernel/.../agent/AgentObserver.java`
   - 症状：hook 仅支持 Java 代码实现，无法通过配置文件定义。
   - 参考：Claude Code 4 种 handler：command(shell) / http(webhook) / prompt(LLM) / agent(子 agent)。
   - 目标：新增 `HookHandler` 接口 + `CommandHookHandler`（shell 执行）+ `HttpHookHandler`（HTTP POST webhook）；从 `application.yml` 的 `hooks:` 配置段加载；保留 `AgentObserver` 作为代码级 hook。
   - 新增事件：`PreCompact`（compaction 前归档 transcript）、`SessionStart`、`Stop`。

6. **Tool Permission Pattern Matching** `agent-kernel/.../agent/ToolPolicy.java`
   - 症状：`ToolPolicy` 按工具名或 `RiskLevel` 做决策；无法表达"允许 Bash 但仅限 `npm run *`"或"禁止 Read `/etc/shadow`"。
   - 参考：Claude Code `Bash(npm run *)` / `Read(~/secrets/**)` glob 模式。
   - 目标：`ToolPolicyRequest` 增加 `args` 字段（已有）；新增 `GlobToolPolicy` 支持 `name(argPattern)` 语法；`ToolPolicy.chain()` 中可混合使用。

7. **MCP Streamable HTTP 演进** `agent-mcp/`
   - 症状：runner 的 MCP transport 尚未跟进 2026 roadmap 的新特性。
   - 参考：MCP 2026 Roadmap — 无状态操作、`Mcp-Method`/`Mcp-Name` header、`ttlMs` 缓存、session migration。
   - 目标：`McpToolClient` 的 HTTP transport 发送 `Mcp-Method`/`Mcp-Name` header；支持 `ttlMs` 缓存（本地 + 分布式）；支持 session resumption。
   - 注意：取决于上游 MCP SDK 0.17+ 的支持程度。

8. **MCP Elicitation 支持** `agent-mcp/`
   - 症状：MCP server 可能发送 elicitation 请求（mid-task 请求用户结构化输入），runner 的 MCP client 会忽略或报错。
   - 目标：`McpToolClient` 注册 elicitation handler；通过 `StreamEvent` 上报给前端；支持 form mode 和 URL mode。

9. **OpenTelemetry 桥接** `agent-kernel/.../trace/`
   - 症状：`Tracer` / `SpanContext` 只传递不落地；`StreamEvent.TRACE` 无 exporter。
   - 目标：`AgentSpanExporter` 将 `StreamEvent.TRACE` 转为 OTel span；`ToolCallingLoop` 每轮迭代 + 每个 tool 调用作为 child span；集成 Jaeger/Zipkin/OTLP exporter。

### P2 — 平台演进与长期架构

10. **Dynamic Workflow 引擎** `agent-kernel/.../orchestrator/`
    - 症状：`SubagentRuntime` 只提供编程式 spawn/wait API；无法表达"对 100 个文件并行执行 lint → 汇总 → 验证"这类编排。
    - 参考：Claude Code Dynamic Workflows（JavaScript 脚本 + agent()/parallel()/pipeline()/phase()）。
    - 目标：设计一个轻量 DSL 或 YAML 编排层；支持 fan-out/fan-in、barrier、phase 分组、budget 控制。
    - 注意：可以基于现有 `SubagentRuntime` 构建，无需引入新的 agent 运行时。

11. **Self-Healing Memory Index** `kernel-memory/`
    - 症状：`MemoryProvider` 做全文/向量检索返回内容片段；无"始终在 context 的轻量指针索引"。
    - 参考：Claude Code MEMORY.md（~150 chars/line 的指针索引，常驻 context）。
    - 目标：`PromptEngine` 在构建 system prompt 时自动拼入一个轻量索引段（key facts / file pointers / session state）；索引由 `MemoryProvider` 维护，每次对话后增量更新。

12. **Feature Flag 系统**
    - 症状：新特性（如 Deferred Tool Loading、Auto-compact、声明式 Agent）需要灰度发布能力。
    - 参考：Claude Code 44 个 feature flag + GrowthBook 集成。
    - 目标：最小实现 `FeatureFlags` bean，基于 `application.yml` + 环境变量；支持 `isEnabled(flag)` 查询；为上述 P0/P1 特性预留 flag。

13. **Step Repetition 检测** `agent-kernel/.../core/ToolCallingLoop.java`
    - 症状：MAST 研究显示 15.7% 的 agent 失败是 step repetition loop（相同工具+相似参数反复调用）。
    - 参考：Berkeley/Stanford MAST taxonomy。
    - 目标：`ToolCallingLoop` 维护最近 N 轮工具调用的 hash 环；连续 M 次相似调用时自动插入"你似乎在重复操作，请重新考虑策略"的系统消息或触发 compaction。

14. **Cost-Tiered Dynamic Model Routing** `agent-kernel/.../orchestrator/AgentFactory.java`
    - 症状：`AgentProfile.modelOverride` 是静态配置；orchestrator 和 worker 使用相同模型。
    - 参考：Claude Code orchestrator 用 Opus / execution 用 Haiku，成本降 5-10x。
    - 目标：`AgentFactory` 根据 `AgentProfile.role`（orchestrator vs worker vs minion）自动选择模型层级；支持配置映射 `role → model`。

15. **Structured Output Validation** `agent-kernel/.../llm/`
    - 症状：LLM 返回的 JSON 工具调用参数无 schema 验证；格式错误只能靠下一轮 LLM 自我纠正。
    - 参考：Claude API `structuredContent` + Pydantic AI schema validation + retry。
    - 目标：`ToolExecutor` 在执行前对 `ToolCall.arguments` 做 JSON Schema 验证；失败时生成友好错误消息回传 LLM 重试（最多 N 次）。

16. **Multi-Channel 适配抽象** `agent-web/`
    - 症状：runner 仅支持 WebSocket + REST；接入 Telegram / Slack / WeChat 等需要大量 ad-hoc 代码。
    - 参考：OpenClaw 20+ channel 统一消息抽象。
    - 目标：设计 `ChannelAdapter` SPI（inbound message → `GatewayRequest`，outbound `StreamEvent` → channel message）；MVP 实现 WebSocket adapter + REST adapter；预留 Telegram/Slack adapter 扩展点。

17. **Durable Execution / Checkpoint** `agent-kernel/.../orchestrator/InterruptibleRun.java`
    - 症状：`InterruptibleRun` 支持 interrupt/resume 但状态仅在内存中；进程重启后丢失。
    - 参考：Temporal durable execution / LangGraph checkpointing。
    - 目标：`InterruptibleRun` 可选持久化到 SQLite（序列化当前 messages + tool state + agent stack）；重启后从 checkpoint 恢复。
    - 优先级低：当前 runner 主要是短会话场景。
