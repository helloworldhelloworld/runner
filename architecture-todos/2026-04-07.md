## 一、外部参考调研摘要

### 1. OpenClaw（2026 年新晋开源 Agent 框架）
五大核心组件，强调**单一进程网关 + 关注点分离**：
- **Gateway**：所有渠道（Slack/WhatsApp/WebSocket…）统一入口，session/路由/鉴权的 single source of truth。
- **Brain**：LLM 编排，标准 ReAct 循环。
- **Memory**：以 Markdown 文件为持久上下文（人类可读、可 diff、可 git）。
- **Skills**：插件式能力，定义清晰输入 schema 与权限。
- **Heartbeat**：调度器，定时巡检收件箱/任务，驱动"主动型"行为。

关键设计：Gateway 与 Agent Runtime **物理分离**；Memory 用 Markdown 而非数据库以利可观测与可移植。

### 2. Claude Code 源码泄露（2026-03-31, v2.1.88 source map 事故）
- **`query.ts` 1729 行 async generator**：`queryLoop` 是单一 `while(true)` 异步生成器，统一以 yield 推送事件，是整套 ReAct 的"心脏"。
- **工具系统强隔离**：每个 Tool 自带 input schema、permission level、execution，**零共享可变状态**。base tool 抽象 ~29k 行。
- **三层上下文压缩**：
  1. *MicroCompact*：本地编辑级，零 API 成本；
  2. *AutoCompact*：接近窗口阈值时触发，生成结构化摘要并保留 token buffer；
  3. *Full Compact*：全量压缩 + 文件按需重注入。
- **隐藏的 KAIROS / PROACTIVE flag**：常驻后台 agent，每隔几秒收到 heartbeat prompt 询问"是否有事要做"——与 OpenClaw Heartbeat 思路同源。
- **Tool Search 模式**：工具数量大时由模型先调"search 工具"再载入相关工具（避免 schema 灌爆 prompt）。

### 3. 2026 社区共识（Anthropic Building Effective Agents、MS Agent Framework、LangGraph 等）
- **简单可组合 > 复杂框架**：单 loop + 单 tool 起步，按需加 streaming / 并行 / 多步链。
- **流式工具调用**：参数生成阶段就开始 stream，让 UI 可以早渲染 tool 进度。
- **Tool single-responsibility**、参数用 enum/min/max 强约束、描述带 example 与 edge case。
- **大工具集走 search-then-load**。
- **权限/审计独立于业务逻辑**，每个 tool 携带 permission level。

## 二、对照现状的差距分析

参考：`docs/architecture.md`、`agent-kernel/.../gateway`、`agent-kernel/.../trace`、`docs/decisions/001~003`。

| # | 维度 | 现状 | 差距 / 风险 |
|---|---|---|---|
| A | **Agent Loop 形态** | `AgentLoop` + `ToolCallingLoop` 双层，递归式调用 | Claude Code 用单一 async generator + 显式 while 循环，状态机更清晰，可在任意点 yield 事件、便于中断/恢复。当前递归不利于中断与回放 |
| B | **上下文压缩** | 仅三层 Memory（Session/Ephemeral/Durable），无主动压缩策略 | 缺 MicroCompact / AutoCompact / Full Compact 的分级；长会话直接受 token 窗口限制 |
| C | **Tool 权限模型** | `Tool` 接口只有 name/desc/schema/execute | 没有 `permissionLevel`，无统一审计/审批面；与 Claude Code 强隔离思路差距明显 |
| D | **Tool Search** | `ToolRegistry` 全量注入 | 工具数量增长后 system prompt 膨胀，缺 search-then-load 机制 |
| E | **Heartbeat / 主动模式** | 无 | OpenClaw 与 Claude Code 都内建心跳驱动主动 agent；`soul-*` 模块（心理陪伴场景）非常适合此模式（主动关怀、定时评估） |
| F | **Memory 可观测性** | `kernel-memory` 走 SQLite + BM25 | OpenClaw 全 Markdown 思路对调试/可移植性更友好；可考虑 SQLite + Markdown 镜像双写 |
| G | **Gateway 抽象** | 已抽象，但 `ChatHandler` 实现散落，session 生命周期与渠道绑定不够清晰 | OpenClaw 把 Gateway 设为 single source of truth；当前 `agent-web` 同时承担装配与协议适配，职责偏重 |
| H | **流式事件粒度** | `Flux<StreamEvent>` 已有 TOOL_CALL_START/PROGRESS/RESULT | 缺 tool argument 增量 delta（partial JSON），UI 无法在工具入参生成时早渲染 |
| I | **Tool 隔离 / 副作用** | 多个 tool 可能共享 registry 之外的状态 | 需逐个审计是否存在跨 tool 的可变共享，向"零共享可变状态"靠拢 |
| J | **可中断 / 可恢复** | 无显式 checkpoint | async generator + 事件溯源能让任意 step 重放；当前递归 + Flux 链路难以做到 |
| K | **PromptEngine 组装** | 字符串拼接 | 缺结构化 prompt segment + token 预算分配（durable / skills / memory snippets 谁先被裁） |
| L | **多 Agent 协作** | 单 agent loop | 2026 主流向多 agent / sub-agent 演化；现 `agent-demo` 未体现 sub-agent spawn |
| M | **可观测性 / Trace** | 已有 `Tracer` / `SpanExporter` | 与 StreamEvent 已联动，但缺与外部 OTel 对齐 + 成本/token 维度指标 |

## 三、待办（按优先级）

### P0 — 影响后续所有迭代的基础重构
- [ ] **T-001 Tool 权限模型**：在 `Tool` 接口加 `PermissionLevel { SAFE, WRITE, EXEC, NETWORK }`，并在 `ToolExecutor` 加统一审批 hook。验收：所有 `agent-tools` 实现声明等级，`mvn clean test` 通过。
- [ ] **T-002 AgentLoop 重构为状态机/生成器**：用 `Flux.generate` 或显式状态对象替代递归，使 step 可中断/可重放。先在 `agent-kernel` 提 RFC 文档至 `docs/decisions/004-agent-loop-state-machine.md`。
- [ ] **T-003 Context Compaction 三层策略**：在 `kernel-memory` + `PromptEngine` 协作实现 MicroCompact / AutoCompact（带 token buffer）/ FullCompact。先做 AutoCompact MVP。

### P1 — 能力扩展
- [ ] **T-004 Tool Search 机制**：`ToolRegistry` 增加 `search(query, k)`；当注册工具数 > 阈值（默认 20）自动切换 search-then-load 模式。
- [ ] **T-005 Heartbeat 模块**：新增 `agent-kernel/.../heartbeat`，最小实现：可注册定时 prompt 注入器，供 `soul-safety` / `soul-assessment` 用于主动关怀与评估提醒。
- [ ] **T-006 Tool argument streaming**：在 `StreamEvent` 增 `TOOL_ARGS_DELTA`，`ToolCallingLoop` 把 LLM provider 的 partial JSON 透传。
- [ ] **T-007 PromptEngine 结构化 + token 预算**：把 system prompt 拆为有序 segment（base / durable / skills / snippets / heartbeat），按预算与优先级裁剪。

### P2 — 工程质量与可观测性
- [ ] **T-008 OTel 对齐**：`SpanExporter` 增加 OTLP exporter；为每次 LLM 调用记录 `tokens.in/out/total` 与 `cost.usd`。
- [ ] **T-009 Tool 副作用审计**：脚本扫描所有 `Tool` 实现，列出含 static / 字段可变状态者，逐一改造为"零共享可变状态"。
- [ ] **T-010 Memory Markdown 镜像**：`FileMemoryManager` 在 SQLite 之外同步落盘 Markdown，便于人工审阅与 git diff。
- [ ] **T-011 Gateway 职责收敛**：把 `agent-web` 中的协议适配层下沉到 `agent-kernel/gateway/adapter`，让 `agent-web` 仅做 Spring 装配。

### P3 — 探索性
- [ ] **T-012 Sub-agent / 多 agent**：调研 `agent-demo` 中加入 sub-agent spawn 的最小 API（参考 Claude Code Task tool）。
- [ ] **T-013 KAIROS 风格主动模式 PoC**：基于 T-005 Heartbeat，做心理陪伴场景的 24/7 关怀 agent demo。
