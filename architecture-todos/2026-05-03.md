## 五、架构合理性总评

### 优势确认

Runner 在以下维度已对齐或领先：
1. **Reactive 流式** — `Flux<StreamEvent>` + typed event enum + factory method，对齐 Claude Code
2. **4 层 Multi-Agent Orchestrator** — ScopedToolRegistry deny>allow，对齐 Claude Code 权限模型
3. **5 种 Tool 供给形态** — SPI + Manual + Plugin + MCP + CLI，超越多数开源框架
4. **Full-duplex 中断/恢复** — InterruptibleRun + CancellationToken，业界少有
5. **3 层内存** — Session + Ephemeral + Durable，对齐 OpenClaw 内存分层
6. **Outside-in TDD** — 场景级 acceptance test 驱动设计，独特优势

### 核心结论

1. **安全是最大短板**：CliTool 命令注入 + API key 泄露是当前唯二 CRITICAL 级问题，应在本周内修复
2. **Compaction 管线完成度 40%**：已有 Snip+Micro，但 Claude Code 的 5 层管线中缺 3 层，长会话稳定性仍有风险
3. **Hook/Lifecycle 停留在 MVP**：同步回调已可用但不够——缺 async/HTTP/agent 变体限制了可扩展性
4. **AAIF 三协议栈成为行业标准**：MCP 已对接，A2A 和 AG-UI 需要提上日程（尤其 A2A 已有 150+ org 生产使用）
5. **Checkpoint/Replay 完全空白**：LangGraph 的 checkpoint 已成金标准，runner 无任何 agent state 持久化能力
6. **基础设施质量债**：3 个 CRITICAL、5 个 HIGH 的代码扫描问题（空 catch 块、无界线程池、blocking in reactive 等）
